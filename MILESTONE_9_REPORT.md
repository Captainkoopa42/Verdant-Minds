# Verdant Minds Independent Rebuild — Milestone 9

## Bounded Active Developmental Workspace

Milestone 9 introduced a finite shared present across the already rebuilt Verdant subsystems.

The workspace coordinates existing records. It does not create semantic truth, evidence, permission, or permanent memory merely by admitting something.

```text
current evidence
+ recalled evidence
+ ECWF possibilities
+ contradictions
+ earned proto-objects
+ active shard context
+ Council constraints
+ authorized non-hardware operations
→ bounded active workspace
```

There is no LLM or pretrained attention policy in this path.

## Purpose

Before this phase, the kernel, claims, ECWF, Council, shards, and objecthood pathway were individually inspectable but were usually invoked separately. The workspace gives those records one limited present in which they can compete for slots and resources.

The constitutional rule is:

> Workspace admission means temporary coordinated availability. It does not establish that a candidate is true, safe, permitted, or permanent.

## Implemented records

### `WorkspacePolicy`

The policy persists:

- total resource budget;
- maximum active items;
- admission and broadcast thresholds;
- persistence duration and carry-forward decay;
- current-evidence reserve;
- ECWF occupancy cap;
- resource-cost penalty;
- explicit experimental score weights;
- policy revision.

### `WorkspaceCandidateInput`

Every candidate records:

- source type and exact source reference;
- diagnostic label;
- evidence lineage;
- requested resources and persistence;
- decomposed scheduling signals;
- optional Council-authorized non-hardware operation;
- bindings to other canonical records;
- metadata.

Source-specific validation prevents a candidate from borrowing unrelated evidence.

### Inspection and commitment

Inspection is pure. A report contains every candidate, decomposed score, rank, admitted and suppressed sets, resource allocation, evictions, state fingerprint, policy revision, and report identity.

A changed source state, changed policy, or altered report makes the report stale or invalid.

Committed workspace cycles preserve:

- the active set;
- broadcast subset;
- exact source and evidence references;
- scores and resource allocations;
- admission and expiry cycles;
- bindings and complete admission lineage.

### Explicit writeback

An active item can be maintained or resolved only through an explicit writeback supported by preserved evidence. Resolution removes the item from the current active set without deleting its history.

## Safeguards

1. Viable current evidence cannot be entirely displaced.
2. ECWF possibilities cannot consume more than the configured budget fraction.
3. Slots and total resources are finite.
4. Evidence lineage is verified against the exact source record.
5. A Council decision authorizes only the exact operation it names.
6. Unresolved items decay or require refresh.
7. Workspace cycles cannot create concepts, relations, claims, contradictions, or evidence.
8. Identical state and candidate inputs replay deterministically.
