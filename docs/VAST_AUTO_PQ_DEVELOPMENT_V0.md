# Native Automatic P and Q Development v0.3

Status: IMPLEMENTED / EXPERIMENTAL on branch test/vast-auto-pq-development-v0, forked from the tested auto-P research branch. Original V5, V5-X, the active v0.65 Obligation Substrate research, previous P-only and 200-experience results all remain unchanged.

## Source audit discovery

Native Q requires **three separate operations** exposed by the original Workbench:

1. Promoted P-to-P interactions: VerdantStructureInteractionPipeline.interact commits evidence about field similarity and independently verified symbolic structural alignment.
2. Hierarchy observation: VerdantHierarchyPipeline.observe consumes *committed interaction evidence* to form a higher-order candidate. Teacher-provided relations, unpromoted P candidates, and field similarity alone are not enough.
3. Hierarchy promotion: VerdantHierarchyPipeline.promote requires native quality, recurrence, pair coverage, alignment/prototype cohesion, boundary selectivity, evidence diversity, and Council authorization; promoted Qs remain opaque and nonsemantic.

These operations are **not** automatically performed by the V5 heartbeat or the original v0.1 integrated curriculum runner.

## Five arms

- v5: genuine full developmental heartbeat, no automatic promotion.
- v5x_observe: same heartbeat with observation-only thermodynamics; must match v5 native canonical fingerprint.
- v5x_auto_p: same development and governed automatic P-only scheduler; no Q.
- v5x_auto_pq: same P scheduler **plus** Q interaction, observation and Council-gated promotion.
- kernel_only: direct native teaching-storage control, no developmental heartbeat.

All arms receive identical compiled experiences and independent native histories. No alteration to quality thresholds, Q policy, governance, teacher testimony, or thermodynamic behavioral control. Runtime/cycle counts must be reported per arm: P+Q naturally performs additional work.

### Prospective Q experimental scheduler

At each completed 20-item curriculum section:

- First process the actual native P scheduler: at most four qualifying Council-authorized Ps promoted for this section in v5x_auto_pq.
- With fewer than **three** native promoted, available Ps, perform no Q interactions. This prevents empty interactions from counting toward native Q recurrence, and supports Ps arriving across separate curriculum sections.
- Starting when three Ps are available, inspect at most **four previously uninspected P sources** per section, each at most once over the run under this policy. A new source is inspected against the accumulated P pool; no fabricated repetition.
- After each native StructureInteraction event, call the actual native Hierarchy observation. Verified alignment, not field-only similarity, is what permits higher-order composition.
- Select eligible Q candidates in deterministic recurrence/ID order. Re-run native Q quality gates, request native Council inspection, and promote at most **two** Council-authorized Qs per section using the same Workbench native hierarchy promotion operation.
- Save Q receipt with interaction source IDs, native events and hierarchy observation IDs, eligible/denied/authorized counts, Council decision IDs and actual layered Q IDs. Every section has a separate durable native VDK and receipt.

The fixed scheduler is an **external developer-designed experiment protocol, not a self-learned Verdant policy**. Zero Q when no P family passes native criteria is a valid scientific outcome.

## Boundary and evidence rules

No automatic Obligation Substrate inquiry, P/Q semantic labelling, thermodynamic behavior-changing control, policy rewriting, structural refolding, simulated knowledge installation, sensor outcomes, or independent general intelligence claims.

Diagnostic VCpack probes inspect reconstruction but are not graded held-out problems. Passing small specially structured Q unit tests demonstrates the native pathway can work; it does not guarantee the real 600-experience curriculum will produce any eligible Q. Actual P count, Q candidate quality, source-lineage, pair verification and resource cost need to be observed under the default policy.

## Prior measured baseline

User's ten-section three-arm result: 200 teaching experiences per arm, 962 native cycles per full-heartbeat arm, 116 concepts, 80 relations, 600 evidence records, 66 active plastic associations and 42 P candidates, no promoted P/Q. A full-heartbeat checkpoint was ~26.31 MiB versus ~3.16 MiB kernel-only; all three arms took 1981 seconds. Performance was superlinear; whole-state copying and validation are plausible contributors, not profiled measurements.

This new experimental version intentionally changes the set of arms and source-lock identity. **Never resume old baseline directories with v0.3**; start new output folders and preserve all earlier artifacts.
