## Why this integration exists

The 12,000-cycle long-horizon retention and 15,000-cycle structural-transfer studies demonstrated bounded private claim persistence and developer-scaffolded path composition. **They did not run the full V5 experience → resonance/ECWF → workspace → plasticity → P-observation heartbeat each cycle.** This increment measures a genuine continuous developmental heartbeat over explicit `.vcpack` teaching commands while retaining a matched direct-kernel control.

The Obligation Substrate's asynchronous workstream has reached **v0.65**. That branch implemented a DependencyGap nucleus, other obligation detectors at distinct maturity, Attention, constrained hypotheses, isolated counterfactual traces, safeguards against simulation leakage, and separately frozen math studies. Its latest supplied repair evaluation does **not** establish autonomous causal repair, semantic understanding, or a generalized learner. The scheduled next item is a **protocol-only**, answer-unseen retention/transfer feasibility assessment within frozen arithmetic bounds; this integration does not modify or replace that task.

## What v0.1 actually runs

The runner imports the **actual Workbench CurriculumCompiler** on the obligation base and compiles each selected `verdant.curriculum.pack.v1` section to typed `ExperienceCommand` records. It preserves the source pack verbatim, its SHA-256, per-section compiled digest and source-code manifest.

Per seed, three private native histories receive identical canonical teaching items:

| Arm | Mechanism | Authority |
|---|---|---|
| `v5` | `VerdantDevelopmentPipeline.advance`, including ECWF resonance, bounded workspace, local plasticity, P-candidate observation | Native developmental processing |
| `v5x_observe` | `V5XDevelopmentPipeline.advance`, with access-pressure and thermodynamic observation on, **thermodynamic behavioral control explicitly off** | Same canonical state as V5; extra observation only |
| `kernel_only` | `VerdantKernel.apply_experience` with the same source commands | Native semantic acquisition without developmental heartbeat |

Native cycles are only teaching experiences—not the number of all internal operations, simulations, probes, or elapsed physical seconds. A run under the user's 30-section, 600-item pack has **600 charged experience cycles per arm**, or 1,800 per seed / 5,400 across three seeds. Two arms execute full developmental heartbeats; one is a canonical-storage negative control.

For each completed section, the runner records an immutable VDK checkpoint, predecessor-linked stage receipt, structural counts, per-probe read-only compilation inspection, and *pure* `DependencyGapDetector.inspect` and `ContradictionObligationDetector.inspect` results. Missing probe cues remain explicitly unknown and do not become scored failure/success. Section tests are diagnostics, not independent held-out answer labels. Results are not graded automatically.

Expected invariant: `v5` and observer-only `v5x_observe` have the same native fingerprint under identical input; all three arms preserve the same canonical concepts/relations/claims/contradictions, while developmental nonsemantic state is allowed to differ. Failure aborts before publishing `results.json`.

## Curriculum-specific obligation boundary

The uploaded pack (SHA-256 `65724b4ad2e9dedf30d9bc00b1e31763b213ba5b65b00edc3701a1504d299bd4`) contains:
- 30 enabled sections × 20 items = **600** teacher-authorized, synthetic text experiences.
- 128-dimensional field.
- 240 declared *diagnostic cues*, not target-answer labels.
- 1,200 supplied relation entries, including `depends_on`; 20 claim entries in Controlled Contradiction.

The v0.2 default DependencyGap detector recognizes the explicit `requires` relation grammar and qualifying Action/Outcome evidence, not arbitrary `depends_on` testimony. **Do not alias `depends_on` to `requires` or manufacture Action/Outcome evidence.** The reader reports how many `depends_on` records exist alongside how many *qualifying* DependencyGap candidates are found. A zero is a meaningful boundary, not a failed integration.

No automatic obligation mutation occurs. Contradiction candidates may arise from authentic native claim conflicts, but an observation does not resolve them. Any future opt-in investigation will require a separate, typed, source-qualified, replayable control request and a matched private shadow cohort.

## Explicit exclusions

- **Not yet implemented:** autonomous obligation scheduling; integrated `DependencyGapInquiryCoordinator.run` across live lessons; all five obligation-family inquiry protocols; native permission for simulated knowledge promotion; behavioral Tg control; P/Q governed promotion; cross-family refolding and operational actuation.
- **Not observed:** teacher-independent relation learning, learned arithmetic, spontaneous learning of traversal procedures, independent source corroboration, cheaper later learning, learned curriculum selection, physical outcome prediction, self-directed goal formation, consciousness.
- The Workbench's existing UI/queue is not modified by v0.1. The runner **reuses its compiler** and the real V5 pipelines, and writes loadable native `.vdk` checkpoints, but does not claim to be a new Workbench UI screen.
- Pack source statements are explicit teacher testimony. The compiler does not convert plain prose into earned semantic interpretation.
- Grammar scaffolds are rejected for this revision rather than silently omitted. There is no automatic repair of source claims.
- No work is committed to V5, V5-X or `test/obligation-substrate-v0`; no tags, merges or pull requests are made.
- The tool has no ability to independently grade the 240 provided cues as correct answers.

## Roadmap in dependency order

1. **v0.1:** Source-frozen full heartbeat + kernel control + V5-X observer + read-only Workbench and obligation diagnostics (this branch).
2. **v0.2:** Hardened Windows section-level resume and deterministic one-, three-, then thirty-section capacity/performance measurements; compare P formation and evidence interference.
3. **v0.3:** Matched governed promotion/compilation-ablation fork study on earned P, then Q eligibility and controlled refolding. No promotion without native quality/authorization.
4. **v0.4:** Opt-in isolated obligation detector → bounded Attention → hypotheses → counterfactual run **on qualified source evidence only**, with zero canonical simulation leakage, exact status/reopen and matched controls. If no qualifying `requires` and Outcome/Action evidence exists, report “not exercised” rather than synthesizing it.
5. **v0.5:** Prospective, preregistered genuinely disjoint held-out transfer tests across sections; measure learning efficiency/teaching cost, not just replayed cues.
6. **Future:** Separate final hardware-agnostic production architecture after mechanism ablations and profiling.

A v0.1 success is a verified integration baseline, **not** a claim that all experimental subsystems have already run together.
